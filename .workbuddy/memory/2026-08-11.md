# 2026-08-11 工作记录

## 修复：InputLocker 菜单栏图标在 macOS 15 (Sequoia) 下不显示

### 根因
1. **NSStatusItem 创建时机（核心回归）**：SwiftUI `App` 生命周期下，原代码在
   `applicationDidFinishLaunching` 内**同步**创建 `NSStatusItem`，macOS 15 菜单栏窗口尚未就绪，
   状态项不会进入菜单栏。社区公认修复：延迟到下一个 RunLoop（`DispatchQueue.main.async`）。
2. **菜单弹出方式脆弱**：原代码 `button.action` + 点击时 `statusItem.menu = menu`
   再 `button.performClick(nil)` 手动弹菜单——该 hack 在 macOS 15 下不可靠。
3. **缺失 LSUIElement**：作为纯菜单栏应用（README 称"不占用桌面空间"）应为 Agent 应用。

### 修改文件
- `InputLocker/App/InputLockerApp.swift`
  - `applicationDidFinishLaunching`：新增 `NSApp.setActivationPolicy(.accessory)`；
    状态项创建延迟到 `DispatchQueue.main.async`（新增 `setupStatusItem()`）。
  - 移除 `statusItemClicked` / `menuDidClose`；改为 `menuWillOpen` 时 `populateMenu` 重建菜单，
    把菜单直接挂到 `statusItem.menu` 由 AppKit 原生弹出。
  - `buildMenu()` 拆出 `populateMenu(_:)`（先 `removeAllItems()` 再填充，保证勾选状态最新）。
- `InputLocker/Info.plist`：新增 `LSUIElement = true`（纯菜单栏 Agent 应用，不再显示 Dock 图标）。

### 验证
- `swiftc -parse` 语法通过。
- `xcodebuild -scheme InputLocker -configuration Release build`（ad-hoc 签名）**BUILD SUCCEEDED**，
  产出通用二进制（arm64 + x86_64），目标 macOS 12.4。
- 注意：菜单栏实际显示需在带 GUI 会话的 macOS 上运行验证，沙箱内无法验证视觉效果。

## 决策确认（19:24）
- 用户确认：**不需要 Dock 图标**，`LSUIElement = true` 维持不变（纯菜单栏 Agent 应用为预期行为）。
